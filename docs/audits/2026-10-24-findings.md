# Newton hardening audit — v0.1.1

## Scope and completion rule

Audited v0.1.0 (`6456c99`) and then re-audited the changes across storage, import, HTTP, workspace/UI lifecycle, build, release, mirror and CI. Newton remains an independently authored small foundation, not the combined source or feature set of Lumen, Vorssaint and Screenpipe. No upstream code was imported; original Lumen files were untouched. The plan is in `2026-10-24-plan.md`.

The five added baseline regression cases initially produced nine failed expectations. After fixes and several targeted passes, all local tests pass: **48 Swift tests across the core/workspace targets and 10 Python delivery tests**. This is a scoped audit result, not proof that future bugs do not exist. The stopping rule is no further reproducible defect in the exercised boundaries, with remaining deployment/integration limits identified below.

## Findings and fixes

| Priority | Original issue | Resolution and evidence |
|---|---|---|
| High | SQLite text bindings used NUL-terminated lengths, collapsing distinct IDs and truncating content | Bind/read exact UTF-8 byte counts. The baseline failed both record-count and round-trip assertions; NUL round-trip, post-NUL FTS search and uniqueness now pass. |
| High | `INSERT OR IGNORE` silently skipped invalid nonfinite timestamps and could conceal unrelated constraints | Validate bounded fields and finite timestamps; ignore only primary-key conflicts. Invalid-input and SQL-trigger failures roll back rows, FTS and metadata together. |
| High | Every open blindly stamped schema version 1, including future databases | Reject unsupported versions without migration; transactional v1→v2 migration, validate schema before commit, re-read the version after acquiring the migration lock. Future-version, migration and failure/rollback tests pass. A later hosted run exposed an intermittent lock failure during concurrent opening/integrity verification. Startup now retries BUSY/LOCKED within a bounded budget, and integrity verification acquires its write transaction before its read cursor, avoiding a read-to-write upgrade. The stress test exercises 32 fresh databases with eight simultaneous openers each; five consecutive repetitions passed (1,280 opener/verification attempts across 160 fresh databases). |
| High | Screenpipe's size check occurred after the complete response was downloaded | A streaming delegate checks Content-Length and each received chunk, cancels oversized downloads, bounds total timeout and owns cancellation/continuation completion. Declared and chunked oversized-body tests pass. |
| High | Failed activity writes had no retained retry buffer; quit depended on view subscriptions and did not drain writes | Extracted NewtonWorkspace; keep unsaved events, pause capture on failures/capacity, offer retry, and join one graceful shutdown task from NSApplicationDelegate. Quit is cancelled on unresolved write/release failures. Failure/retry, stop/flush and concurrent-shutdown tests pass. |
| High | File-size preflight could be invalidated before an unbounded read; no import cancellation | Open a single no-follow/nonblocking descriptor, require a regular file, enforce a 25 MB cumulative read limit, 1 MB line limit and record/field limits. Propagate cancellation before commit; reject non-file URLs and symlinks. Nonregular/oversized/mismatched input tests pass. |
| Medium | A stopped capture session could leave queued callbacks; rapid stop/quit could discard accepted writes | Session identity guards at both native adapter and workspace boundary; RAII observer removal; drain accepted events independently of the capture toggle. Stale callback and actual isolated NSWorkspace-notification adapter tests pass. |
| Medium | One task, transaction and history refresh per event scaled poorly | One ingestion worker writes batches of up to 128 and avoids full history queries while hidden. A 2,000-event burst uses 16 append transactions and one initial history page, retaining every accepted event. Capture pauses at 4,096 pending events instead of allowing indefinite queue growth. |
| Medium | Only the newest 100 events were reachable; equal timestamps lacked deterministic paging | Keyset pagination on timestamp+ID, an ordering index and visible Load More. 1,001 tied-timestamp rows are retrieved exactly once; the workspace reaches all 251 fixture rows beyond its first page. |
| Medium | Search invalidation started after debounce; old results could publish during that gap | Invalidate immediately on query changes, check generation on completion, budget SQLite query execution and return a consistent page/count snapshot. Delayed-query and punctuation/Unicode adversarial tests pass. |
| Medium | Screenpipe rows could produce duplicate SwiftUI IDs or accept objects as identities | Validate scalar identities, normalize type namespaces, deduplicate and cap decoded rows, expose omitted-row count. Baseline duplicate/object cases fail before the fix and pass afterward. |
| Medium | Query/credential changes could leave results associated with obsolete input; orchestration was not injectable | Request ownership tokens, edit/cancel invalidation, in-memory credentials, fixed loopback endpoint, no redirects/proxies/cookies, injected transport and deferred connector tests. Original code already had some Task cancellation guards; no claim that every stale-request scenario was a demonstrated baseline failure. |
| Medium | Modal picker state and imports/deletion could overlap; failures left no useful retry/cancel path | Async picker with global operation ownership, import cancellation, deletion exclusivity, startup retry and per-view confirmation state. The failed file read cannot commit after cancellation; shutdown does not wait indefinitely on a cancelled cloud-provider read, but drains active DB writes. |
| Medium | Keep-awake release errors were ignored and resources lacked fallback ownership | Power assertion RAII, explicit release errors, truthful enabled state on failure, and termination independent of workspace windows. Mock release-failure tests and native assertion smoke checks cover both paths. |
| Medium | Existing data directories could retain broad permissions | Validate a normal directory and apply mode 0700 before opening history. Isolated permissions test passes. The database remains unencrypted; this is not a new encryption claim. |
| High | Failed builds could leave partially replaced live app contents | Build/sign/package in a private staging directory; source-change detection, build lock, rollback of all prior outputs if publication fails. Disposable tests inject signing and mid-publication failures and compare previous bytes. |
| High | Mirroring could pair committed source with an unrelated ZIP and retain deleted source files | SHA-256 receipt binds version, build inputs, binary and ZIP. Mirror verified immutable commit/archive snapshots, guard concurrent publication and atomically publish current.json. Changed source, tampered ZIP, stale version, dirty tree, symlinked input and exact snapshot tests pass. |
| Medium | Failed push left a bumped release with no safe repeat path, and memory claimed push before success | Journal commit/push/mirror phases; resume the same release without another bump; verify remote branch/tag; preserve concurrent edits and refuse unrelated state. A local bare-repository hook rejects push, then resume succeeds at the same version and commit. |
| Medium | Swift 6.1 on the macOS15 runner crashed lowering the cross-module actor-isolated default initializer in an NSObject stored property | Keep live default construction inside NewtonWorkspace and initialize the application delegate explicitly. Both hosted environments must compile and run the regression suite; the newer local compiler alone did not reveal this. |
| Low | Hosted checks covered one environment and floating action tags | CI runs macOS 15 and 26, uses verified fixed action revisions, scoped permissions and timeouts. Hosted CI is verified separately from local test success. |

## Performance evidence

`2026-10-24-benchmarks.json` contains three sequential release-binary runs per revision on the same Mac, each using 10,000 synthetic events in a disposable SQLite database.

| Median measurement | v0.1.0 | v0.1.1 |
|---|---:|---:|
| Insert 10,000 events | 117.77 ms | 124.17 ms |
| Reinsert same 10,000 IDs | 16.97 ms | 16.80 ms |
| Recent 100 rows | 0.140 ms | 0.180 ms |
| Common-term search | 4.070 ms | 4.230 ms |
| Project conjunction | 0.341 ms | 0.354 ms |

These small single-host samples do **not** demonstrate an overall speedup. Validation, count bookkeeping and stable ordering add overhead. The material measured structural improvement is batching and removal of hidden full-list recomputation. No CPU, battery-life, multi-day memory or UI frame-rate claim is made.

## Validation boundaries and remaining work

- Live Screenpipe deployment/authentication and actual user Lumen files are not exercised; network/file fixtures avoid reading private history. Actual native notification adaptation is tested with a private NotificationCenter and the test process, not continuous global activity.
- SQLite quick-check/FTS integrity checks, transaction failure, migration and reopen are covered. Automatic salvage of a physically corrupted database is not implemented; Newton reports failure instead of resetting it.
- Cancellation prevents a read that finishes later from starting a new import commit. It cannot undo a commit that already completed; the UI says so. A cloud provider can still block its OS read until the process exits; that cancelled read cannot write later.
- SQL search has a cooperative two-second VM budget, with a separate 1.5-second busy timeout. This is not a strict whole-app latency guarantee. Large imports serialize through the store and may delay reads.
- App data is not encrypted and has no automatic retention policy; deletion is logical, not forensic erasure. Screenpipe's independent policies still apply.
- Delivery fixtures verify failure handling without running real signing/network services. The actual packaged app is separately ad-hoc signed and verified; not notarized. A crash/kill can leave locks that require PID inspection rather than unsafe automatic deletion.
- Native smoke: existing history migrated to schema 2 and remained present; the opt-in native activity service persisted a new event. A real keep-awake assertion was created, then quit after closing the workspace window terminated the process and released the assertion. The user’s three enabled switches were restored afterward. A protected local backup was excluded from Git/iCloud. Hosted matrix runs are checked separately before delivery.
- iCloud is a local verified snapshot mirror, not proof of server upload.
