# Newton hardening audit plan

Baseline: v0.1.0 / 6456c99. Scope: every source file, tests, package/build/release/mirror scripts, hosted CI and app lifecycle. No upstream code merge or new capture permissions. Original Lumen untouched.

1. Record baseline and inspect all boundaries. Prioritize reproducible data loss, privacy/resource hazards, stale tasks and release mistakes over cosmetic changes.
2. Harden storage/import contracts: schema compatibility and transactional migrations, exact text round trips, input validation, cancellation/rollback, deterministic pagination, bounded selected-file reads.
3. Harden connector: enforce a download limit during reception, timeout/cancellation/redirect and proxy policy, strict stable IDs and deduplication, injected network tests independent of private history.
4. Extract testable workspace orchestration: generation ownership for network requests, single ingestion worker, startup/retry/teardown contracts, asynchronous file picker, exclusive deletion/import, graceful application termination. Reproduce toggle races and write failures with injected services.
5. Check UI reachability, status/error/retry/cancel states, pagination, feature stop behavior, and multi-window implications. Test real native controls with disposable app data only when appropriate.
6. Repair release tooling: staged packaging, provenance receipts, resumable failure states, safe mirror publication and exact version/artifact matching. Test scripts in disposable repositories with fake build/network commands.
7. Repeat the audit against changed code. Run regression, stress/adversarial fixtures, release packaging/signature, hosted CI and native smoke checks. Re-test failures after fixes; avoid repeating unaffected checks without a reason.
8. Publish findings with reproduction/validation and unresolved limits, increment Newton patch version, commit/push and mirror source/artifact plus synchronized memory. Stop when the scoped passes and required checks reveal no further reproducible defect; do not imply absence of all future bugs or full parity with three upstream apps.

Known first-pass candidates: post-download size check; stale remote task completion; NUL string truncation; unconditional user_version stamp; ignored bind errors; nonfinite timestamps silently ignored; unbounded import read after preflight; no history pagination; repeated full list refresh on each event; pending writes on app quit; stale notification after stop/start; synchronous open panel and overlapping operations; artifact/version/commit mismatch possible in mirror; release log claims push before it succeeds; incomplete release failure recovery.
